## 不进行真实支付的端到端验证

使用可调试模拟器或已开启 USB 调试的测试设备，安装并启动 App 后：

1. 手动新增测试规则：名称 `Shell 测试`，包名 `com.android.shell`，关键词 `支出`，默认排除词，启用。
2. 在系统设置授予 MoneyTrack 通知读取权，在“设置”检查连接状态。
3. 通过 SDK 的 adb 执行（adb 需要在 PATH 中；使用虚构金额）：

```powershell
adb shell cmd notification post -t "MoneyTrack test" moneytrack-demo "支出12.50元"
```

4. 首页应出现一条待确认；确认前总额不变，点击确认后增加 12.50 元。
5. 换一个 tag 发同额通知，应出现另一条候选，不能仅因同额而去重。
6. 发送 `退款 支出12.50元` 应不新增记录。停用规则后再发正常文本，也应不新增。
7. 忽略一条记录，重新打开 App，检查它仍被隐藏；确认记录、规则和总额应持久化。
8. 删除测试规则，避免后续 shell 通知影响账本。

注意：`cmd notification` 支持情况随系统而异，先执行 `adb shell cmd notification help` 查看语法。Windows 终端/adb 对中文参数的编码可能不同；若乱码，可临时把关键词改为 `spent`，发送 `spent CNY 12.50` 验证同一链路。重复执行 post 命令通常会产生新的时间，**不能用于证明同一事件重复回调去重**。

- 规则页：卡片显示名称、包名和启停状态，点击打开对应规则。

## 常见问题

**Gradle 启动失败或 class file version 不支持**：检查 Android Studio 的 Gradle JDK 与终端 JAVA_HOME，使用 JDK 17 和仓库 Wrapper。

**测试报找不到 `GradleWorkerMain`**：若 Windows 用户目录带单引号，Gradle 8.13 生成的 Java 参数文件可能错误解析该路径。把 Gradle 用户目录设到不含单引号的位置，再运行构建。例如在仓库根目录执行 `$env:GRADLE_USER_HOME = Join-Path $PWD '.gradle-user-home'`；此缓存目录已被忽略。Android Studio 可在 Gradle 设置中指定同一 Gradle user home。首次换目录需要下载或复制已有缓存，不需要更换项目依赖版本。

**SDK location not found**：用 Android Studio 打开根目录生成 `local.properties`，或手工填写 `sdk.dir`。不要提交这个本机文件。

**依赖下载失败**：构建需要访问 Google Maven、Maven Central 和 Gradle 分发站点。检查自己的网络/代理设置；不要在仓库写入个人代理密码。

**侧载后通知使用权不可开启**：部分 Android 版本会限制侧载应用的敏感设置。按系统在应用详情中的提示操作；本项目不绕过该限制。

**授权后尚未连接**：先在“设置”点击“尝试重新连接”，观察是否变为“已连接”；再检查系统通知使用权和手机后台限制。必要时由用户在系统设置关闭再重新开启授权。不要把请求重连成功误当成服务已经连接。

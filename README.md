# MoneyTrack

一个适合边学边开发的 **原生 Android 通知记账 App**。采用 Kotlin + XML/ViewBinding + SQLite，最低支持 Android 8.0（API 26）。核心代码配有中文注释。

## 当前功能

- Material 3 青绿色界面：金额概览、状态卡片、分组表单，跟随系统切换深色模式。
- 带图标的应用选择页，支持按名称或包名搜索；也可以手动输入包名。
- 逐条添加、编辑或删除支出匹配条件和排除词，保存后按来源启用或停用；支持 `{金额}`、受限 `{无关文字}`，括号等其余文字固定匹配；排除词可留空。
- 应用规则使用紧凑卡片，条件按编号单行编辑，长文本可横向移动；表单输入时自动滚动避让键盘，“今日账本”标题旁可直接刷新。
- “设置 → 通知配置”集中进入应用识别规则、主副通知联动、配置导入导出。
- 主副通知联动：用户指定支付应用和银行卡应用，同金额通知在主通知前后各 30 秒内可合并为一笔待确认账单，窗口可调整；优先向前找副通知，一对一匹配并持久保留双方身份。
- 通过系统文件选择器备份 JSON 通知配置，预览后按包名和主副组合合并，保留启停状态，兼容旧规则文件；不包含账单、标签或系统授权。
- 内置微信“已支付…元”、支付宝“你有一笔…元的支出／元支出”的**关闭状态示例规则**，需结合实际脱敏通知测试后启用。
- 引导用户到系统设置授权 `NotificationListenerService`。
- 通知匹配后保存“待确认”支出；确认后计入总额，可以忽略或移除记录。
- “今日 → 手工记一笔”：填写金额、来源名称（选填），用滚轮选择日期和时间，保存即确认，不需要通知授权。
- 点击账单编辑文字备注、多个标签和报销状态（无报销／待报销／部分报销／已报销）；仅统计已确认账单的未报销金额。
- 自定义标签可从“设置 → 标签管理”或账单表单跳转增删改，以紧凑单行显示名称、更名与删除。
- 底部导航分为“今日／历史支出／设置”：今日显示全部待确认和当天已确认记录，历史支持按日、周、月浏览及报销状态筛选。
- 今日与历史页向上滚动时，标题和筛选区先收起，金额概览卡片到顶后固定，账单列表继续滚动；回到列表顶部后可下拉展开标题和筛选区。
- 记录每次加载 100 条，可加载更多；统计覆盖所选时间段的全部已确认记录。
- 设置的“通知识别”卡片集中管理通知读取授权、后台识别和重连；后台识别通过同一个按钮开启/关闭，开启后显示可关闭的常驻通知。
- 表单内测试通知文本，预览结果不会入账。
- 离线保存，不申请网络权限，不保存通知原文；支持清空账本。

**能力边界：** 只能读取系统实际交付的通知。支付 App 不发通知、通知隐藏金额、厂商限制后台运行等情况下，可能无法记录；聊天消息也可能包含类似支付文本，所以首版要求人工确认。它不是支付平台官方账单接口，也不会补抓授权前的历史通知。

## 在 Android Studio 中运行

1. 打开本仓库根目录 `MoneyTrack`。
2. 在 Android Studio 设置的 **Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK** 中选择 **JDK 17**。
3. 在 SDK Manager 安装 **Android SDK Platform 36** 和 **Android SDK Build-Tools 35.0.0**（AGP 默认版本），以及 Platform-Tools。
4. 让 Android Studio 生成本机的 `local.properties`。手动配置时可写 `sdk.dir=E\:/Android/sdk`，请替换成自己的路径；冒号需要转义，此文件已被 Git 忽略。
5. 等待 Gradle Sync，选择 `app`，运行到 Android 8.0 以上设备或模拟器。首次构建需要联网下载工具和依赖。

依赖版本固定为 AGP 8.13.2、Kotlin 2.3.10、Gradle 8.13。不要直接用机器上的 Gradle 9 或默认 JDK 24 替换。版本依据：[AGP 官方兼容说明](https://developer.android.com/build/releases/agp-8-13-0-release-notes)、[Kotlin 兼容矩阵](https://kotlinlang.org/docs/gradle-configure-project.html)。

PowerShell 示例（JDK 路径替换为你自己的安装目录；只影响当前终端）：

```powershell
$env:JAVA_HOME = 'C:\Path\To\jdk-17'
$env:GRADLE_USER_HOME = Join-Path $PWD '.gradle-user-home'
.\gradlew.bat :core:test
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

上面的项目内缓存路径可避开 Windows 用户目录含单引号时的 Gradle 测试启动问题。本机已用此路径完成初始化构建；Android Studio 的 **Gradle user home** 也应指向仓库下 `.gradle-user-home`，不要把它误填到 Gradle 安装目录栏。

macOS/Linux：

```sh
chmod +x gradlew
./gradlew :core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。Gradle Wrapper 的脚本与 JAR 已包含在仓库中，分发包配置了 SHA-256 校验。

## 第一次体验

1. 进入底部“设置 → 通知配置 → 配置支付 App”，编辑预设或添加应用。
2. 在测试区输入虚构文本 `支付成功 ￥12.50`，点击“测试当前规则”，应识别为 `¥12.50`。
3. 再测试 `退款：支付成功 ￥12.50`，应不匹配。
4. 打开启用开关，保存规则。回到“设置”，点击“管理通知读取授权”，阅读说明后进入系统设置授权。
5. 等待对应 App 的新通知；成功匹配后在“今日”核对待确认记录。详情点击“记录支出”同时保存附加信息并确认，之后按报销状态计入总额。当天已确认仍留在今日页；历史页可按日、周、月查询已确认支出。
6. 若手机划掉任务后会中断监听，在“设置 → 通知识别”点击“开启后台识别”，允许显示通知后会继续开启，确认常驻通知与“已连接”状态后再测试。原按钮随状态变为“关闭后台识别”，也可从常驻通知关闭该模式。

记录按设备本地时区归档：通知使用到达时间，手工记录使用填写的支出时间；周从周一开始，今天确认的旧通知仍属于原来的通知日期。持续监听改善进程存活，但不能保证强制停止、厂商清理后继续工作。撤销通知读取授权会停止此模式，重新授权并返回应用时，会尝试恢复之前开启的持续监听；手动关闭后不会自动开启。

测试区只测试文本规则，不测试系统授权、通知投递或数据库。无真实通知时，可按 [测试指南](docs/TESTING.md) 使用开发用通知验证完整链路。

## 手工补记

在“今日”页点击“手工记一笔”，填写以元为单位的金额，按需填写来源（例如虚构测试使用“测试现金”），上下滑动滚轮选择日期和时间，按需添加标签、备注和报销标记，点击“保存为已确认支出”。来源留空时显示“手工记账”，列表会标注“已确认 · 手工记账”。

金额必须大于零，最多两位小数，单笔不超过一亿元；仅填写数字，不带货币符号、千分位或单位。金额以 `BigDecimal` 精确转换成分，不自动舍入。当天的记录出现在今日与对应历史区间；补记以前日期的记录只出现在对应的历史日、周、月中。

不需要规则或通知授权；取消返回不会保存。保存后点击记录进入详情，可编辑附加信息或移除；待确认详情只有一个“记录支出”按钮，保存并确认账单。每次新开表单可分别保存同额支出，同一表单重复保存不会重复入账。手工记录不会和之后的支付通知自动合并，如又识别到同一笔交易，需要人工核对候选。

## 备注、标签和报销

点击今日或历史中的任意账单打开详情。可以填写最多 500 字符的备注，选择最多 8 个标签，查看当前报销状态，并在“修改为”下拉菜单中选择新状态。待确认点击“记录支出”同时保存并确认，已确认点击“保存修改”更新信息。未确认账单始终不计入统计。

- **无报销**：不申请报销或报销失败，计原金额，列表不显示报销徽标。
- **待报销**：仍计原金额，整张账单卡片显示待报销底色和文字。
- **部分报销**：填写累计已报销金额（大于零、最多两位小数；达到或超过原支出时，失焦自动转为已报销），统计只计未报销部分，整张卡片显示部分报销底色，同时展示已报金额和计入支出金额。
- **已报销**：计入支出为零，账单与原金额保留，整张卡片显示已报销底色和文字。

今日与历史使用相同统计口径，抵扣归属原支出日期，不生成收入。历史页标题旁的筛选按钮打开带状态色点与选中标记的圆角面板，可筛选全部、待报销、部分报销、已报销或无报销；列表、笔数、总额均使用相同筛选。筛选待报销后点击账单修改，保存返回即刷新。已报销记录仍计入账单笔数。

标签可在“设置 → 标签管理”新增、更名和删除，也能从账单横向标签栏右侧的“＋ 管理”按钮跳转。内置吃饭、服饰、交通、日用品作为可编辑的起始标签。拖动手柄上下调整顺序，账单选择栏与标签显示同步采用该顺序，新标签排在末尾、更名保留位置。更名同步到关联账单；删除后已有账单保留该标签的名称快照，修改备注或报销时也保留；在账单内主动取消选择才移除。删除后可重新创建同名标签，新旧标签互不影响。

版本 0.2.0 将数据库从 v1 迁移到 v2，保留已有账单、规则和去重身份。覆盖安装升级即可，卸载会删除本地账本。

版本 0.2.1 将数据库升级至 v3，保留账单、备注和标签，为仍使用旧默认关键词的微信、支付宝规则分别补上“已支付…元”和“你有一笔…元支出”。自定义关键词保持原样，可在规则编辑页点击“载入此应用默认支出关键词”后测试并保存；排除词和启停选择不会被自动改变。默认配置来自用户提供的格式，尚未验证真实支付通知；详细句式见 [规则说明](docs/RULES.md)。

版本 0.2.2 将数据库升级至 v4，为支付宝默认规则补上“你有一笔…元的支出”，兼容上一版不带“的”的句式。覆盖安装仅更新已知旧版的完整默认关键词，账单与自定义配置保留。更新后需等待新通知，之前漏记的通知不会自动补抓，可使用手工记账补录。

本次报销调整将数据库升级至 v5，追加新的报销状态和已报销金额列，迁移原报销状态，保留账单、标签关联、规则与通知去重身份。旧版的“已报销”记录升级后按新口径计零，原支出金额保留；应用版本号保持不变。

前次界面调整将数据库升级至 v6，新增已删除标签的账单快照表，不重建账本；应用版本号仍保持不变。旧版已经删除的标签关联无法从现有数据库恢复。

本次调整将数据库升级至 v7，为标签追加持久化顺序；已有账单、快照和规则保留。报销卡片改用独立的玫瑰、紫、蓝配色，待确认仍用黄色。应用版本号保持不变。

## 通知连接与后台设置

配置页提供 3 步引导：选择来源并测试、启用规则 → 在系统授权通知读取 → 确认已连接并检查新通知。测试器来源为 `com.moneytrack.testapp`。测试文本匹配成功不代表系统连接或规则已经启用。

若显示“已授权，尚未连接”，先点“尝试重新连接”；仍不成功时打开通知读取设置，由你关闭再重新开启 MoneyTrack 的读取授权，返回确认“已连接”。诊断区只显示接收时间和处理结果，不保存通知原文。

持续监听与系统通知入口分开；被回收不会清除开启选项，返回应用时在权限满足后尝试恢复。系统清理仍可能结束进程，可在应用详情检查后台自启动、省电策略，并按需要在最近任务中锁定应用；不同系统版本的入口可能不同。应用不能绕过用户强制停止或系统安全限制。模拟器已验证任务移除后的接收，真机行为仍需确认。

规则编辑不再用逗号合并条件；每条独立编辑，逗号保留为该条内容。`支出(消费{无关文字}){金额}元` 匹配“支出(消费虚构商户)12元”或“支出(消费)12元”，固定括号和消费文字不能省略。排除词可全部留空，空白行不参与匹配，详细语法与边界见 [规则说明](docs/RULES.md)。已有规则列表、启停选择和账本保留，应用及数据库版本号保持不变。

## 代码从哪里读

```text
MoneyTrack/
├── AGENTS.md                      # 后续 AI 协作、注释与工程约定
├── core/                          # 无 Android 依赖的业务逻辑与单元测试
│   └── src/main/kotlin/com/moneytrack/core/
│       ├── PaymentRule.kt         # 配置模型及输入校验
│       ├── PaymentRulePresets.kt  # 精确包名的支付格式预设与旧默认更新
│       ├── ExpenseParser.kt       # 文本 → 金额（分）
│       ├── ManualExpense.kt       # 手工金额校验与草稿身份
│       └── NotificationIdentity.kt # 通知去重指纹
├── app/src/main/
│   ├── AndroidManifest.xml        # 页面、服务、可见应用范围
│   ├── java/com/moneytrack/app/
│   │   ├── MoneyTrackApplication.kt # 共享数据库与后台线程
│   │   ├── notification/          # 系统通知回调
│   │   ├── data/                  # SQLite 持久化
│   │   └── ui/                    # 账本、规则列表、编辑页面
│   └── res/                       # XML 布局、字符串与主题
└── docs/                          # 架构、规则与测试学习资料
```

建议顺序：[学习与架构](docs/ARCHITECTURE.md) → `PaymentRule` → `ExpenseParser` 和对应测试 → 通知服务 → 数据库 → 页面。

详细格式见 [规则说明](docs/RULES.md)，验证步骤见 [测试指南](docs/TESTING.md)。本地 SQLite 受 Android 应用沙箱保护，**没有额外做数据库加密**；卸载或清除应用数据会删除账本。项目关闭系统备份并排除云备份和设备迁移。
